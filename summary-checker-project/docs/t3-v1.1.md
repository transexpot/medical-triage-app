# ТЗ v1.1 — Исправление freeze-дефектов

**Статус:** DRAFT  
**Основание:** SPEC_DEFECT-003, SPEC_DEFECT-004  
**Условие начала спринта:** закрыть 003, 004 и 005  

## 1. Цель v1.1

Исправить противоречие `data_complete` и `DEADLINE_MISSED`,
а также создать карту оснований проверок.

## 2. Изменение 1: data_complete

`data_complete` — свойство данных,
а не свойство времени.

`data_complete = true`, если:

- все обязательные поля присутствуют;
- все присутствующие критические поля имеют дату,
  единицы и источник;
- нет блокеров;
- нет открытых уточнений;
- нет значений в карантине по критическим полям.

Условие «дедлайн не истёк» исключается.

`DEADLINE_MISSED` остаётся отдельным статусом
и отдельным признаком времени.

## 3. Изменение 2: check_basis_map.json

Создаётся файл:

```text
summary-checker-project/src/summary_checker/check_basis_map.json
```

с версией:

```text
check_basis_map_version = v1.0
```

Карта должна содержать основание для каждой проверки:

- `patient_identity`
- `value_date_present`
- `value_source_present`
- `unit_valid`
- `glucose_condition_valid`
- `value_readable`
- `contract_compliance`

## 4. Утверждение

Оба изменения требуют двойного утверждения:

1. Владелец чек-листа.
2. Внешний рецензент.

## 5. Порядок работ

```text
1. Исправить data_complete.
2. Создать check_basis_map.json.
3. Получить двойное утверждение.
4. Закрыть SPEC_DEFECT-003.
5. Закрыть SPEC_DEFECT-004.
6. Написать реальные тесты.
7. Заполнить трассируемость.
8. Закрыть SPEC_DEFECT-005.
9. Начать первый спринт.
```
